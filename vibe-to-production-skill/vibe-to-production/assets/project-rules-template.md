# Security and Production Rules

These rules apply to all AI-assisted development sessions in this project.
Generated by the vibe-to-production skill after a production-readiness audit.

---

## Secrets and credentials

- NEVER hardcode API keys, tokens, database credentials, or secrets in source code — use environment variables only
- NEVER commit `.env`, `.env.local`, or `.env.production` files — these are in `.gitignore`
- NEVER put secret-tier keys (Stripe `sk_...`, Supabase `service_role`, private keys, database connection strings) in any variable prefixed with `NEXT_PUBLIC_`, `VITE_`, `REACT_APP_`, or `EXPO_PUBLIC_`
- If you need a new secret, add the variable name (no value) to `.env.example` and tell me what value to set

## Authentication and authorization

- Every API route or server function that reads or mutates non-public data MUST verify that the request is authenticated before doing anything else
- Every query that retrieves user-scoped data MUST filter by the authenticated user's ID in the query itself — do not fetch a record by ID and check ownership after the fact
- Do NOT assume the frontend is showing only "the user's own data" provides protection — the backend must enforce it too

## Database

- Do NOT use `service_role` or equivalent admin/bypass keys in frontend/client code
- Do NOT disable Row-Level Security (RLS) on any table that holds user data
- Do NOT apply schema changes by running raw SQL manually — use the migration system ([Prisma Migrate / Supabase migrations / Alembic / other])
- All user-facing list queries MUST include a `limit`/`take` to prevent unbounded result sets

## Mobile-specific (if applicable)

- Do NOT use AsyncStorage / SharedPreferences / UserDefaults for tokens, credentials, or any sensitive user data — use Keychain (iOS) / Keystore (Android) via the secure storage library in use
- Do NOT hardcode API keys or secrets in the app bundle — they will be extractable by anyone who decompiles the binary

## Error handling

- API routes MUST handle errors and return appropriate HTTP status codes (401 for unauthenticated, 403 for unauthorized, 404 for not-found-or-not-yours, 400 for validation errors, 500 for unexpected errors)
- Do NOT return stack traces, internal error messages, or database error details to the client in production — log them server-side only
- Do NOT swallow errors silently (empty catch blocks)

## Dependencies

- Before adding a new npm/pip/pub package, verify it exists and is legitimate on the registry — AI-suggested package names are sometimes hallucinated
- Do NOT install packages with `--force` or `--legacy-peer-deps` without understanding what conflict is being overridden
